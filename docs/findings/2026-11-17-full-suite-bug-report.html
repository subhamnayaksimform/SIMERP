P1 High

BUG-01

Employee and CSM can read the Goals APIs

Goals · TC-EMPGOL-515 · Security

  1. Log in as an Employee user (or a CSM user).
  2. With that session call:
    • GET /api/v1/employee-goals/dashboard?timeFrame=15d
    • GET /api/v1/employee-goals/filter-options
    • GET /api/v1/employee-goals/employees?page=1&limit=100
Expected
403 for all three. These roles have no Goals screen.
Actual
200 for all three, for both Employee and CSM.
BUG-02

TM can edit any goal through the API

Goals · TC-EMPGOL-519 · Security

  1. As Admin, create a goal that is not assigned to anyone.
  2. Log in as a TM user.
  3. Send PATCH /api/v1/goals/<goal id> with { "description": "test" }.
Expected
403. The TM should only change goals in their own departments.
Actual
200, and the goal is changed. (POST /api/v1/goals for another department correctly fails with 400.)

This is the same as finding F-1 from the 13/11 re-test (goal writes by RM/TM/EM). Please confirm the rule with product, since the goal list is org-wide.

BUG-03

Dashboard can't be reached from the sidebar

Dashboard · TC-DASH-001, 021, 022

  1. Log in as any role and look at the sidebar.
  2. Log in as an Employee user and open /dashboard.
Expected
“Dashboard” is the first sidebar item, and Employees can open it (FRD sections 3 and 10).
Actual
  • No role has a Dashboard link. The sidebar starts with Overview, Employee, Team and so on.
  • Employees are sent to /unauthorized, and their sidebar only shows Employee › Certifications.

The Employee part is already filed as DEF-DASH-001 (Zoho 688906000093525946). The missing link for all roles looks like it was removed by mistake in frontend commit 756c6c6b (“fix-merge-conflict”, 15/09). No release note mentions it.

BUG-04

Saving Sagar Khanpara's record always fails

Employee Details · TC-EMPDET-003, 033, 043

  1. Log in as Admin and open Employee.
  2. Click Edit on Sagar Khanpara (the first row in the default sort).
  3. Change any field, for example Overall Rating, and click Save.
Expected
The record saves and the drawer closes.
Actual
PATCH /api/v1/employees/818aa719… returns 400 “Team does not belong to the specified department”. The drawer stays open and nothing saves, whichever field was changed.

First seen 10/09, still happening. Probably his team and department data are out of step. This also blocks the double-click Save check (TC-EMPDET-033).

BUG-05

Project page shows the 90-day figure for “Last 15/30 days”

Working Location · TC-EMPWLC-010

  1. Log in as a CSM user and open any project's detail page.
  2. Click a member's Working Location cell. The popup shows different office % for 15, 30 and 90 days.
  3. Change the time-range dropdown to “Last 15 days”, then to “Last 30 days”.
Expected
The column shows the 15-day figure, then the 30-day figure.
Actual
It shows the 90-day figure both times (for example 83% where the 15-day figure is 89%).

Cause: the project page doesn't send timeFrame to the API.

BUG-06

Employee list shows another range for “Last 5 days” / “Last 6 months”

Working Location · TC-EMPWLC-009

  1. Log in as Admin, open Employee and turn on the Working Location column.
  2. Note Punit Patel's figure for “Last 15 days” and for “All time”.
  3. Choose “Last 5 days”, then “Last 6 months”.
Expected
The 5-day and 6-month figures, or a clear note that this range isn't available.
Actual
“Last 5 days” quietly shows the 15-day figure, and “Last 6 months” shows the all-time figure. The API maps timeFrame=5d to the 15d window and 6m to overall.

BUG-07

Clear doesn't reset “No Goals Assigned”

Goals › By Employee · TC-EMPGOL-444

  1. Log in as Admin and open Goals › By Employee. The footer shows “of 3648 results”.
  2. Open the Goals column filter, turn on No Goals Assigned and Save. The footer shows about 1,223.
  3. Open the same filter and click Clear.

BUG-08

% and _ in search match everyone

Goals › By Employee · TC-EMPGOL-459

  1. Open Goals › By Employee.
  2. Search for %, then for _.
Expected
Only names that contain those characters, which is usually 0.
Actual
% returns 3,648 of 3,648 rows and _ returns 3,647. The server treats them as wildcards.
BUG-09

Duplicate goal names allowed if case or spaces differ

Goals › By Goal · TC-EMPGOL-494

  1. Create goal AUTO-GOL-123-dup.
  2. Create AUTO-GOL-123-dup again. Blocked with 409, which is correct.
  3. Create auto-gol-123-dup (lower case).
  4. Create AUTO-GOL-123-dup   (with trailing spaces).
Expected
Steps 3 and 4 are blocked as duplicates, like step 2.
Actual
Steps 3 and 4 both save (201).

BUG-13

A bad filter in the URL breaks the whole My Projects page

My Projects · TC-PMPROJ-128

  1. Log in as a CSM user.
  2. Open /my-projects?adv_allocationStage=FOO.
Expected
The bad value is ignored, or a readable message is shown with a way to clear it.
Actual
The API returns 400 and shows the toast Filter "allocationStage" must be a non-empty array of: …. The whole page is replaced by “Failed to load projects”, which hides search and the stats cards. There's no way to clear the filter apart from editing the URL.
